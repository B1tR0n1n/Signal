# SIGNAL – project instructions

Original Minecraft adventure mod. Full brief: `docs/HANDOFF.md`. Status: `docs/IMPLEMENTATION_STATUS.md`.

- Platform (owner decision 2026-10-10, superseding the brief's Forge 1.20.1): **Minecraft Java 1.21.1,
  NeoForge 21.1.256 (pinned), Java 21**, official NeoForge ModDevGradle MDK and its Gradle wrapper. Chosen
  so the official Iris shader loader is available. Do not switch loader/version or replace the wrapper
  without the owner. Linux is first-class.
- Mod id `signal`, package `io.github.b1tr0n1n.signal`. Verify 1.21.1 API signatures against the NeoForge
  sources JAR or the decompiled game; see `docs/COMPATIBILITY.md` for gotchas already found.
- Game rules live in `domain/` (pure Java, JUnit-tested). Minecraft code validates on the server and
  projects state onto blocks; block entities hold only a node id. Client classes stay in `client/`; payload
  handlers that touch them are only invoked on the physical client.
- Worldgen JSON (biomes, features, world preset) is generated by `tools/gen_worldgen.py`; edit the script,
  not the JSON. Keep feature order consistent across biomes (the script's check must report 0 conflicts).
- Never change ordinary worlds automatically; scenario changes happen only via `/signal scenario ...` and
  are announced. Scenario writes go through `SiteCanvas`, which enforces the planned bounds.
- Before claiming a feature: `./gradlew build` (unit tests) and `./gradlew runGameTestServer` (integration).
  Report graphical testing separately from build/test results; shader output cannot be verified here.
- Record reversible decisions in `docs/DECISIONS.md` and every shipped asset in `docs/ASSET_PROVENANCE.md`.
  No copied or ripped assets; textures come from `tools/gen_textures.py`.
- Never commit `run/`, worlds, or credentials.
